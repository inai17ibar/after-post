# Branch Namer — 日本語からの英語ブランチ名提案

日本語の作業説明を、そのリポジトリで実際に使われている命名規則に合わせた英語ブランチ名に
変換する。良いブランチ名は「チームの他のブランチと並んだときに違和感がないこと」が最重要
なので、翻訳の前に必ずリポジトリの実態を観察する。

## 手順

### 1. リポジトリの命名規則を観察する

まず最近のブランチ名をサンプリングする：

```bash
git branch -a --sort=-committerdate | head -30
```

観察するポイント：

- **type プレフィックス**: `feature/` `fix/` `docs/` `feat/` など、何が使われているか。
  リポジトリによっては type なしのフラットな名前が主流のこともある。多数派に従う。
- **チケット ID の形式**: `feature/VIV-187-port-ai-...` のように ID を含む慣習があるか、
  ID の位置（プレフィックス直後か）、大文字か。
- **区切りと語数**: kebab-case が普通だが、まれに snake_case のリポジトリもある。
  典型的な語数・長さも見ておく（3〜6 語程度が多い）。

`renovate/` や `codex/`, `claude/` のようなボット・ツール由来のブランチは慣習の
サンプルとして数えない。

### 2. 日本語入力を解釈する

- **チケット ID の抽出**: 入力に `VIV-102` `SCA-154` `S3-367` のような
  `[A-Z][A-Z0-9]*-[0-9]+` パターンがあれば抽出し、大文字に正規化して名前に組み込む。
  なければ ID なしの形式で提案する（ID を尋ねて手を止めない）。
- **type の推定**: 「修正」「バグ」→ `fix`、「追加」「実装」「対応」→ `feature`/`feat`、
  「ドキュメント」「メモ」→ `docs`、「リファクタ」→ `refactor` など。
  迷ったら候補間で type を変えて提示すればよい。
- **本質の抽出**: 日本語の説明は文脈語（「〜の件」「〜について」「〜による」）を含み
  がち。ブランチ名に残すのは対象と動作だけ。直訳ではなく、コードレビュアーが一目で
  作業内容を掴める要約を作る。

### 3. 候補を 2〜3 個提案する

命名ルール：

- 小文字 kebab-case、ASCII のみ（プロダクト名などの固有名詞はローマ字可）
- type プレフィックスの後の `/` 以外にスラッシュを増やさない
- 全体で 50 文字程度まで。短すぎて曖昧になるより、1 語足して明確な方がよい
- 先頭・末尾のハイフン、連続ハイフンを作らない

候補はニュアンスを変える（例: 簡潔版 / 詳細版 / type 違い）。それぞれ一言の根拠を
添えて AskUserQuestion で提示する。推奨候補を先頭に置く。

対話できない状況（サブエージェント実行など）では、質問せずに候補リストを根拠つきで
出力して終える。

### 4. 選ばれた候補でブランチを作成する

```bash
git switch -c <選ばれた名前>
```

- 作成前に `git branch --list <名前>` で衝突がないか確認する。
- 現在のブランチが作業途中（uncommitted changes あり）でも `switch -c` は変更を
  持ったまま新ブランチに移るので通常は問題ない。ただし現在ブランチがユーザーの
  意図した分岐元でなさそうな場合（例: 別のフィーチャーブランチ上にいる）は、
  分岐元をデフォルトブランチにするか一言確認する。
- ユーザーが「既存の日本語名ブランチを直したい」文脈なら、新規作成ではなく
  `git branch -m <旧名> <新名>` でリネームする。リモートに push 済みの場合は
  リモート側の旧ブランチ削除と再 push が必要になることを伝えてから行う。

## 変換例

**例 1 — チケット ID あり:**
入力: 「VIV-102 の遅延パスレンダリングのバグを直すブランチを切って」
候補: `fix/VIV-102-delayed-path-rendering`（推奨・簡潔）,
`fix/VIV-102-delayed-path-rendering-flicker`（症状まで含む詳細版）

**例 2 — ID なし・機能追加:**
入力: 「シーン生成に空の再着色機能を追加する」
候補: `feature/scene-sky-recoloring`（推奨）, `feat/add-sky-recolor-to-scene-gen`

**例 3 — 日本語ブランチ名の直訳依頼:**
入力: 「『fableによるバグ調査と修正』を英語にして」
候補: `fix/fable-bug-audit-and-fixes`（推奨）, `chore/fable-bug-audit`
（調査主体なら chore/docs 寄りもあり得ると説明を添える）
